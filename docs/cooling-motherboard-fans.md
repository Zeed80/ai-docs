# Управление вентиляторами материнской платы

Вентиляторы видеокарты NVIDIA работают сразу и ничего доустанавливать не
требуют: NVML умеет и задавать обороты, и штатно вернуть кривую прошивки.
Достаточно включить `FAN_CONTROL_ENABLED=1` — см. раздел «Включение».

С вентиляторами CPU и корпуса сложнее, и упирается это **не в приложение, а в
драйвер ядра**. Приложению нужна в `/sys/class/hwmon` пара файлов:

* `pwmN` — с правами `0644`, то есть драйвер согласен принимать запись;
* `pwmN_enable` — переключатель «1 = ручной режим, 2 = кривая прошивки».

Без `pwmN_enable` вентилятор нечем вернуть прошивке, поэтому такой канал мы не
трогаем вообще: захватить управление и не иметь пути назад — худший вариант из
возможных. Как только эта пара появляется, приложение подхватывает канал само,
править его код не нужно.

> **Важно.** Всё ниже зависит от вашей конкретной платы. Плата на этом стенде —
> MSI с чипом Nuvoton NCT6687D, и ей нужен внешний модуль ядра. Вашей может не
> понадобиться ничего, а может понадобиться совсем другое. Поэтому начинайте не
> с установки, а с диагностики.

## Шаг 1. Диагностика

```bash
bash infra/scripts/fan-control-setup.sh
```

Режим по умолчанию **ничего не меняет**: он показывает плату, найденные чипы,
все каналы с оборотами и правами на `pwm`, и говорит, что делать именно в вашем
случае. Пример с этого стенда:

```
== Железо ==
  ядро:              6.17.0-41-generic
  материнская плата: Micro-Star International Co., Ltd. MAG B850M MORTAR WIFI

== Датчики и вентиляторы (hwmon) ==
  чип nct6687  (/sys/class/hwmon/hwmon2)
    канал 1: 1098 об/мин   pwm: ТОЛЬКО ЧТЕНИЕ (режим 444, pwm_enable нет)
    ...
    канал 13: 1238 об/мин   pwm: канала нет
```

Читается так: у каналов 1–4 есть PWM, но драйвер отдал их правами `444`, то
есть только на чтение; каналы 13–16 — чистые тахометры, обороты видно, задать
нельзя (так разведены разъёмы на плате).

### Возможные вердикты

| Вердикт | Что значит | Что делать |
|---|---|---|
| **Драйвер уже отдаёт PWM на запись** | повезло, всё есть | ставить нечего, идите к шагу 4 |
| **NCT6683 / NCT6687** | штатный драйвер `nct6683` пишет pwm только платам Mitac и не создаёт `pwm_enable` | шаг 2 — единственный случай, который скрипт умеет ставить |
| **NCT677x / NCT679x** | штатный `nct6775` запись поддерживает, но здесь она закрыта | внешний модуль **не нужен**, см. ниже |
| **ITE IT86xx / IT87xx** | частые у ASRock и Gigabyte, многие ревизии штатный драйвер не пишет | есть внешний драйвер [it87](https://github.com/frankcrawford/it87), но здесь он не проверялся |
| **Чипов с вентиляторами не видно** | драйвер Super-I/O не загружен | `sudo apt install lm-sensors && sudo sensors-detect`, затем перезагрузка |
| **Случай неизвестен** | чип есть, рецепта нет | ищите свою плату в вики lm-sensors или в списках поддержки CoolerControl |

**Про NCT677x/679x.** Если у вас этот чип и pwm закрыт, обычная причина — ACPI
держит порты чипа, и драйвер отказывается их трогать. Лечится параметром ядра
`acpi_enforce_resources=lax` плюс выключением Smart Fan Mode в BIOS. Скрипт этот
случай намеренно не автоматизирует: параметры ядра — слишком общая правка,
чтобы делать её за вас втихую.

Если сервер имеет BMC (в диагностике появится строка про `/dev/ipmi0`), то
вентиляторами почти наверняка распоряжается он, а не hwmon, и работать нужно
через `ipmitool`. Наше приложение такие платы не поддерживает.

## Шаг 2. Установка модуля (только для NCT6687D)

```bash
sudo bash infra/scripts/fan-control-setup.sh --install
```

Скрипт сначала повторит диагностику, затем перечислит, что именно собирается
сделать, и **спросит подтверждение**. Если вердикт не «NCT6683 / NCT6687», он
откажется работать — переубедить можно флагом `--force`, но тогда вы сами
отвечаете за результат.

Что он делает:

1. доставляет недостающие пакеты `dkms`, `git`, `build-essential`,
   `linux-headers-$(uname -r)` — только через `apt`, на других пакетных
   менеджерах остановится и попросит поставить их вручную;
2. собирает и регистрирует в DKMS модуль [nct6687d](https://github.com/Fred78290/nct6687d);
3. пишет `/etc/modprobe.d/blacklist-nct6683.conf`, чтобы штатный драйвер не
   занял чип первым;
4. пишет `/etc/modules-load.d/nct6687.conf` для автозагрузки.

Любой существующий файл он сохраняет рядом с суффиксом `.bak-<дата-время>`.
Повторный запуск безопасен: уже собранный модуль пропускается.

### То же самое вручную

```bash
sudo apt install dkms build-essential linux-headers-$(uname -r) git
git clone --depth 1 https://github.com/Fred78290/nct6687d
cd nct6687d && sudo make dkms/install

echo 'blacklist nct6683' | sudo tee /etc/modprobe.d/blacklist-nct6683.conf
echo nct6687 | sudo tee /etc/modules-load.d/nct6687.conf
```

## Шаг 3. BIOS и перезагрузка

Два пункта в разделе управления вентиляторами:

* **`Smart Fan Mode` — выключить.** Иначе прошивка продолжит крутить
  вентиляторы по своей кривой и будет перебивать наши записи. Приложение это
  заметит (тахометр не совпадёт с заданным) и уведёт канал в аварию.
* **`Fan Type Auto Detect` — включить** для всех подключённых вентиляторов,
  чтобы плата правильно определила PWM/DC.

Затем перезагрузитесь: модуль ядра подменяется только при загрузке.

## Шаг 4. Включение в приложении

В `infra/.env`:

```
FAN_CONTROL_ENABLED=1        # разрешить запись оборотов вообще
FAN_CONTROL_ALLOW_HWMON=1    # разрешить каналы материнской платы
```

Первая переменная нужна и для вентиляторов GPU, вторая — только для платы.
Обе по умолчанию `0`: возможность писать в вентиляторы не должна включаться
сама по факту развёртывания.

Есть и третье условие: `AGENT_SERVICE_KEY` должен быть настоящим ключом, а не
значением-заглушкой из `docker-compose.yml`. С заглушкой запись оборотов
отклоняется с 403, хотя телеметрия продолжает работать. Сгенерировать:
`bash infra/scripts/gen-secrets.sh`.

Перезапуск:

```bash
docker compose -f infra/docker-compose.yml -f infra/docker-compose.prod.yml \
  up -d gpu-temp-helper
```

Каналы определяются один раз при старте контейнера, поэтому после установки
драйвера перезапустить его обязательно.

## Шаг 5. Проверка

```bash
sudo bash infra/scripts/fan-control-setup.sh --verify
```

Ожидается «модуль nct6687 загружен» и ненулевое число записываемых PWM-каналов.
Если каналов ноль, а модуль загружен — почти всегда не выключен Smart Fan Mode.

Затем откройте **Настройки → Охлаждение**: каналы платы должны стать
управляемыми, а в столбце «Состояние» вместо причины появиться диапазон
оборотов. Быстрая проверка без записи в железо — кнопка «Проверить (без записи)»
в редакторе кривой.

## Откат

```bash
sudo bash infra/scripts/fan-control-setup.sh --uninstall
```

Удаляет модуль из DKMS и убирает оба созданных файла (сохранив копии). После
перезагрузки вернётся штатный `nct6683`. Не забудьте вернуть
`FAN_CONTROL_ALLOW_HWMON=0` и, если выключали, Smart Fan Mode в BIOS.

---

## Что будет при обновлении ядра

DKMS пересобирает модуль сам. Если сборка упадёт (обычно из-за несовместимости
с новым ядром), плата вернётся под управление BIOS: каналы снова станут
`controllable: false`, в интерфейсе появится объяснение. **Перегрева не будет** —
вентиляторами в этом случае распоряжается прошивка. Пропадёт только наше
управление, до починки модуля.

Проверить состояние: `dkms status`, `lsmod | grep nct6687`.

## Приложение: почему права проверяются по битам режима

И скрипт, и сам сервис определяют, писабелен ли `pwmN`, по битам режима файла
(`0644` против `0444`), а не вызовом `os.access(W_OK)` / `test -w`. Причина в
том, что и то и другое выполняется от root, а root обходит права доступа и
отвечает «да» даже для файла `0444`. Из-за этого первая версия интерфейса
уверяла, что вентиляторы платы управляемы, хотя ни одна запись не проходила.
Драйвер сообщает своё намерение именно правами: `0644` — «буду крутить»,
`0444` — «отказываюсь».
