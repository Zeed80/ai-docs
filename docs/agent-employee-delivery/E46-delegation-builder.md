# E46 — конструктор постоянных разрешений

Дата: 10 октября 2026.

## Было

Экран `/settings/delegations` принимал ограничения свободным JSON. Сервер
проверял только непустоту и запрет пары служебных ключей: поле, которого
действие не передаёт, неверный тип или «*» проходили — разрешение выглядело
узким, а на деле либо не совпадало ни с чем, либо значило не то.

## Стало

- **Поля из самого эндпоинта.** `domain/delegations.delegation_fields` берёт из
  OpenAPI приложения скалярные параметры пути, запроса и тела действия с типом и
  форматом (`invoice_id` — string/uuid, `delete_files` — boolean). Действия без
  таких полей не предлагаются: их нечем сузить.
- **Сервер проверяет каждое ограничение** (`check_constraints`): поле должно
  быть у каждого делегируемого действия, значение — своего типа (uuid — валидный
  UUID, целое — не bool), непустое; подстановочные слова (`*`, `all`, «любой»…)
  и коллекции отклоняются. Ошибка — 422 с понятной причиной.
- **Экран**: выбор действия → поля этого действия с подсказкой типа; пустое
  поле не ограничивает, но выдать разрешение без хотя бы одного точного
  значения нельзя. Над кнопкой — фраза («Агент сможет выполнить X, только если
  …; не больше N раз, до …») и точный итоговый JSON.
- Неделегируемое осталось неделегируемым: admin-only, чтение, `execute`,
  `interact`, неизвестные операции; cron — по-прежнему только расписание и
  SHA-256 промпта.

## Проверено

Неизвестное поле, неверный тип, не-UUID, `*`, пробел, список — 422; истёкший
срок не даёт полномочий; отзыв — сразу; две параллельные последние попытки —
ровно одна проходит (строка разрешения блокируется на время учёта).
`python3 -m pytest backend/tests/test_agent_delegations.py -q`;
`cd frontend && PLAYWRIGHT_MOCK_API=1 npx playwright test tests/e2e/delegations.spec.ts --project=chromium`.
