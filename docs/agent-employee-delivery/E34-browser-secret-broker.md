# E34 — брокер паролей браузера; вход, MFA и CAPTCHA

Дата: 10 октября 2026. Gate D2 (review до настоящих учётных записей) — за
владельцем.

## Брокер

- Пароль сохраняет только человек: `POST /api/browser-secrets {label, origin,
  value}` (вызов от агента — 403). Значение шифруется (`secret_box`), origin
  нормализуется до `scheme://host[:port]`. Список и ответы — без значения.
  Отзыв: `POST /api/browser-secrets/{id}/revoke`. Создание и отзыв — в аудите,
  без значения. Таблица `browser_secrets` (миграция `20261010_0005`) — секретная
  для SQL агента.
- Грант заказа называет секреты (`secret_ids`) и должен содержать действие
  `desktop_fill_secret`; можно назвать только живые секреты владельца заказа.
- `desktop_fill_secret {ref, revision, secret_id}`: бэкенд проверяет, что секрет
  назван грантом, принадлежит владельцу заказа, не отозван и ещё не
  использовался под этим грантом (гонка двух попыток закрыта счётом записей
  аудита), расшифровывает и передаёт сервису браузера значение и origin. Модель
  видит только `secret_id`.
- Сервис вводит значение только в поле `type=password` главного фрейма страницы,
  чей origin совпадает с секретом (`origin_mismatch`, `not_a_password_field`), и
  только по свежему `ref`/`revision` (E32).
- Значение не возвращается: снимки не показывают значения полей пароля; если
  страница повторяет его в тексте, другом поле, URL или заголовке, сервис
  вычищает его из всех ответов сессии (`•••`). Ошибки валидации сервиса не
  повторяют вход (иначе 422 вернул бы пароль). Аудит хранит `secret_id`, не
  значение.
- Остаток риска: скриншот — изображение; если сайт сам показывает пароль
  открытым текстом, он виден на скриншоте. Защита — привязка к origin: на
  чужом сайте значение не вводится.

## Вход с MFA и CAPTCHA

CAPTCHA не обходится. Код MFA агент не вводит и не подбирает — передаёт сессию
владельцу (T3, 2026-10-12):

- `computer_use.desktop_handoff {reason}` — сессия переходит к владельцу заказа;
  доступно любому гранту с `desktop_start`. Ответ даёт `owner_url`
  (`/work-orders/browser?work_order_id=…&session=…`). Пока сессия у владельца,
  любое действие агента в ней — `session_with_owner`.
- Владелец (человек; вызов от агента — 403, чужой заказ — 404):
  `GET /api/computer-use/sessions?work_order_id=` и
  `POST /api/computer-use/sessions/{id}/human {op: view|take|click|type|key|return}`.
  Ввод — как у человека: щелчок по координатам снимка, набор с клавиатуры,
  клавиши Enter/Tab/Shift+Tab/Backspace/Escape/стрелки/Space. Действовать
  можно только в переданной сессии (`take` — взять самому).
- Набранное владельцем (от 4 символов) вычищается из ответов агенту, как
  секрет: код MFA до модели не доходит. В журнале (`computer_use_actions`,
  `owner_<op>`) — «ввёл владелец» и длина, без текста.
- `return`: агентский `observe` до передачи становится устаревшим
  (`stale_revision`), нужен новый; если страница вне allowlist гранта, сессия
  закрывается, а не возвращается агенту.
- Экран: «Браузер сотрудника» — живой снимок раз в 3 с, щелчок по снимку,
  поле ввода, клавиши, «Взять сессию» / «Вернуть сотруднику». Секреты —
  «Настройки → Браузер».

Остаток: снимок, а не поток — на сайтах с быстрой анимацией владелец видит
кадр с задержкой до 3 с.
