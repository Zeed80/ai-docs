# E45 — единая страница работы

Дата: 10 октября 2026.

## Что на странице `/work-orders`

- Шапка поручения: цель, описание, канал (`source`), владелец, ревизия плана,
  текущий шаг, статус человеческим словом (`display_status`), блокер, итог.
- Новые панели: **бюджет линии** (предел и израсходовано по каждому измерению,
  `GET /api/work-orders/{id}/budget`), **приёмка** (критерии и кто проверил,
  `/criteria`), **решения** (указания, пауза, гранты и их отзыв, вердикты,
  сверки, согласования — из журнала событий).
- План, вызовы инструментов с доказательствами, согласования на шаге, память
  исполнения — как раньше.

## Контракт сервера

- `WorkOrderOut.display_status`: запрошенная, но ещё не наступившая пауза —
  `pause_requested`, а не «выполняется». «Принято и завершено» — только
  `completed`; ответ чата «готово» заказ не завершает.
- `WorkOrderOut.available_actions`: какие переходы примет API сейчас
  (`run`, `pause`, `unpause`, `cancel`, `instructions`). Кнопки страницы — ровно
  эти; эндпоинты по-прежнему проверяют сами. Закрытое поручение — без кнопок.

## Надёжность экрана

- Запоздалый ответ по прежде выбранному поручению не перерисовывает текущее.
- Ответ неожиданной формы оставляет панель пустой, а не роняет страницу (так
  падали e2e: мок отдавал `{}` вместо массива).
- Ошибка действия — уведомление, ошибка загрузки — баннер.
- Мобильная ширина 320/412 px — проверена e2e.

## Найдено по ходу

e2e поручений и журнала чата были сломаны с 6 октября: приложение проверяет
сессию (`/api/auth/me`) и продлевает её (`POST /api/auth/refresh`), а моки
этих тестов о них не знали — страница уходила на логин, проверка «нет записей»
ловила продление сессии. Починено.
