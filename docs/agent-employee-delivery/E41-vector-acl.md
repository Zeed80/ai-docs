# E41 — права в векторном индексе; spec-таблицы агента

Дата: 10 октября 2026.

## Spec-таблицы (найдено при аудите)

`workspace.spec_table` компилирует спецификацию прямо в SQL от владельца базы.
Права применялись только к источнику `emails`; счета, их строки, платежи,
документы, чертежи и аномалии отдавались за все отделы любому, кто попросит
агента. Теперь `table_spec._row_scope` добавляет условие, которое спецификацией
не снять: всё следует за видимостью документа (`document_visibility_filter`),
аномалия — за своим счётом или документом. Без пользователя видны только ничьи
и общие строки. Виртуальные источники: `vector_search` фильтрует в Qdrant и
перепроверяет документы по БД, `graph_query` берёт лучший ВИДИМЫЙ узел и
видимые рёбра (`GraphAccess`).

## Векторный индекс

- У каждой точки с текстом документа (вектор документа, фрагменты, evidence; все
  коллекции `documents__*`) есть payload `acl`: `owner`, `dept`, `shared`
  (тип документа общий — `SHARED_DOCUMENT_TYPES`), `v`.
- Поиск ограниченного пользователя фильтрует по `acl` внутри Qdrant
  (`vector.acl.acl_filter`): чужие фрагменты не занимают top-k и не попадают в
  реранкер или модель. admin/manager — без фильтра.
- Индекс не авторитет: найденное перепроверяется по БД перед выдачей текста,
  поэтому отставание `acl` стоит полноты, а не утечки.
- Точки без `acl` (записанные раньше) для ограниченного пользователя не
  находятся — карантин, а не «видно всем».
- Синхронизация: при записи точки; после коммита, меняющего владельца, отдел или
  тип документа (событие ORM → задача `vector.sync_document_acl`; в воркерах
  ставится по `worker_process_init`, в бэкенде — на старте); полная — на старте
  и ночью (03:40). Полная синхронизация удаляет точки исчезнувших документов.

## Попутно (E44): удаление не чистило векторы

`delete_document` удалял одну точку из коллекции `documents`, которой давно нет;
профильные коллекции хранили векторы и тексты фрагментов каждого удалённого
документа — 308 таких точек на стенде. Теперь удаление стирает все точки
документа во всех `documents__*` по `doc_id`/`document_id`, а ночная
синхронизация добирает пропущенное.
