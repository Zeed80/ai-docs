# E22 — Пауза на безопасной границе (между шагами)

Дата: 6 октября 2026. Исполнитель и приёмка: Claude Code (root).

## Контракт

- `POST /api/work-orders/{id}/pause`: намерение хранится в `metadata.pause`
  (без миграции). Пока оно есть, `claim_ready_step` не выдаёт новых шагов —
  фильтр в запросе и повторная проверка после блокировки заказа (гонка с
  запросом паузы).
- Подтверждение (`status = "paused"`, `pause.acknowledged_at`,
  `pause.previous_status`) — только когда ни один шаг заказа не выполняется:
  сразу, если так уже есть, иначе — тиком диспетчера
  (`acknowledge_pause_requests`) после завершения начатого шага. Начатый шаг
  доделывается и не считается отменённым.
- Подтверждается из `received/planning/ready/running/replanning`; в
  `verifying`/`waiting_*` запрос ждёт перехода в одно из них.
- `POST /{id}/unpause`: права владельца проверяются в момент возобновления;
  возврат в рабочее состояние (`running/ready → ready`, `planning`,
  `replanning`, `received → planning`); общий ledger не сбрасывается. До
  подтверждения тот же вызов отзывает запрос (`work.pause_withdrawn`).
- Повторный запрос — без второго события; отмена после паузы разрешена;
  терминальный заказ — 409.
- UI (`/work-orders`): «Пауза запрошена — ждём завершения текущего шага» и
  «Приостановлено безопасно»; кнопки «Пауза» / «Продолжить».

## Не входит

Пауза внутри одного выполняющегося хода агента (на границе инструмента в
durable chat) — чатовый ход доделывается целиком. Решение по approval при
приостановленном заказе ждёт возобновления.
