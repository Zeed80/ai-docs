## Выявленные расхождения и границы

- `agent_control.task_propose`: catalog задаёт `admin_only=False`, однако реальный `backend/app/api/agent_control_plane.py:1030` требует `require_role(UserRole.admin)`. Это catalog/backend RBAC divergence; E03 не ослабляет endpoint. При корректном `Idempotency-Key` этот handler использует `prepare_proposal_receipt`/`record_proposal_receipt` и коммитит `AgentTask` и `WorkEvent` одной финальной транзакцией. Legacy-вызов без ключа коммитит только `AgentTask`.
- Catalog `admin_only` и RBAC target handler — разные enforcement layers. В матрице зафиксированы обе; исправление несовпадений требует отдельной карточки. В частности `task_create`, `task_decide`, `task_run` и `capability_propose` имеют admin/human-admin target handler; E03 не меняет их доступ.
- Неоднозначный/неразрешимый FastAPI target, indirect helper, нулевой или множественный direct commit остаются `unknown`; это не требование мигрировать legacy route. Для каждого `unknown` automatic retry запрещён.
- Capability dispatcher до downstream proxy выполняет actor/RBAC/approval/delegation и audit. Его audit commit не является commit boundary recipient-а в этой матрице.

## Кандидат E08

Выбран единственный кандидат: `agent_control.task_propose` → `POST /api/agent/tasks/propose` → `AgentTask`. У варианта с валидным idempotency key уже есть order lock, receipt и единый финальный commit без внешнего dispatch. Он не включён массово: сначала E07/common receipt contract, отдельное решение catalog/admin divergence и сохранение legacy пути без ключа. E03 не реализует E08.
