## Как права устроены сейчас

| Объект | Поле | Кто видит | Где применяется |
|---|---|---|---|
| Документ, счёт, дело | `owner_sub`, `department_id` | admin/manager — всё; остальные — свои, своего поддерева отделов и «ничьи» (legacy) | `app/domain/access.py` (`visibility_filter`) в API документов, счетов, дел |
| Факт памяти | `scope`: `owner:<sub>`, `session`, `department:<id>`, `project`, `global` | своё, своя сессия, свой отдел, `project`, `global` | `api/memory.py` (`_authorize_memory_scope`, `_resolve_visible_scopes`) |
| Почта | ящик (личный / общий) | личный — только владелец, агент — по правилам ящика | `app/domain/email_access.py` |
| Рабочий заказ, артефакт | `owner_key` заказа | владелец | API work orders, брокер E28 |
| Производное: чанк, evidence, узел графа | `source_document_id` | как исходный документ | **поиск памяти — с этого среза** |
| SQL агента (`workspace.sql_table`) | — | все строки 7 таблиц; при полном доступе — все таблицы | только роль СУБД, **строк не фильтрует** |

## Правила

1. **Область видимости выбирает, но не выдаёт права.** `global` и `project` не
   значат «любой текст, который модель назвала общим»: писать в них может только
   путь с проверкой полномочий (`_authorize_memory_scope`).
2. **Производное не шире источников.** Чанк, evidence span, узел графа и
   embedding видны только тому, кто видит исходный документ. Несколько
   источников — пересечение прав.
3. **Неизвестное происхождение — карантин, а не admin.** Производный объект без
   источника не должен становиться видимым всем.
4. **Одна функция политики**, точки применения: SQL-выборки API, граф, вектор
   (Qdrant), кэши, скачивание, фоновые сборщики, переиндексация, удаление.

## Найдено

- **Исправлено в этом срезе (`_drop_invisible_document_hits`).** Поиск памяти
  (`search`, `explain`, `query` — все идут через `search_memory`) отдавал
  чанки, evidence и узлы графа с текстом документов других отделов. Теперь
  результаты с недоступным исходным документом отсекаются до подсчёта и
  пагинации. Тест: `tests/test_memory_document_visibility.py`.
- **Пробел (E39, нужно решение).** SQL-путь агента не знает строковых прав:
  под ролью `agent_sql_reader` видны все счета и документы всех отделов, а при
  включённом полном доступе — и чужая почта. Варианты:
  (a) SQL агента — только в ходах admin/manager;
  (b) Postgres Row Level Security на ролях агента с `SET LOCAL app.user_sub`
  действующего пользователя — права применяет сама СУБД, рекомендую;
  (c) оставить как явное решение оператора.
- **Пробел (E40).** Узлы графа, привязанные к сущности (`entity_type`/`entity_id`,
  например счёт) без `source_document_id`, фильтром не покрыты.
- **Пробел (правило 3).** Документы без владельца и отдела (legacy) видны всем, а
  с ними и всё производное. Это совместимость, а не карантин; закрыть
  backfill-ом владельцев (Gate E1).
