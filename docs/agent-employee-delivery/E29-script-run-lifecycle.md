# E29 — Жизненный цикл ScriptRun

Дата: 10 октября 2026. Исполнитель и приёмка: Claude Code (root).

## Контракт

Шаг вида `script` (план строит владелец; шаблон планировщика этот вид не
допускает, в каталоге агента его нет) исполняется `run_script_step`
(`app/domain/script_runs.py`). Выключено флажком `settings.script_runs_enabled`
до Gate C (E30): выключенный шаг падает с `script_runs_disabled`, не доходя до
supervisor-а.

1. **Намерение до запуска.** `AgentScriptRun` со статусом `queued`
   коммитится первым. Ключ `script:<idempotency_key шага>` одинаков у всех
   попыток шага и уникален в таблице.
2. **Повтор не запускает код вслепую.** Завершённый запуск переиспользуется.
   Запуск, оставленный `running` погибшим воркером, сверяется с supervisor-ом:
   его записанный результат принимается; если supervisor его не знает, контейнер
   убит вместе с ним, а без сети и общей ФС за пределами песочницы ничего
   случиться не могло — повторная отправка безопасна. Пока supervisor исполняет
   — повтор шага позже (`ScriptRunPending`), без нового job.
3. **Журнал и бюджет общие.** Вызов шага идёт в `work_tool_calls`
   (исполнитель `script`), обращение к supervisor-у — одна попытка
   `tool_attempts` на общей книге заказа.
4. **Состояния запуска** — `queued, running, succeeded, failed, timed_out,
   canceled, refused, unknown` — отдельно от успеха задачи пользователя.
   Неуспешный запуск даёт окончательный провал шага с кодом
   `script_run_<status>`.
5. **Выходы** публикуются брокером E28 только из `succeeded` и только пока
   попытка держит аренду — в том же `commit`, что и итог запуска. Устаревшая
   попытка записывает итог, а файлы — нет (`outputs_withheld`).
6. **Журналы** ограничены 64 КБ (supervisor), в итоге — только поля из списка.
7. **Отмена заказа** помечает его запуски `canceled` в той же транзакции и
   после `commit` просит supervisor убить контейнеры. Отмена, пришедшая раньше
   самого запуска, оставляет у supervisor-а «надгробие»: запоздавший запрос с
   этим `run_id` получает `canceled`, не исполняясь (найдено тестом: отмена
   успевала раньше создания контейнера, и код спал все 60 секунд). Отмена в
   окно между записью запуска и созданием контейнера тоже ловится: supervisor
   проверяет флажок отмены до и сразу после старта контейнера.
8. **Недоступный supervisor** — `refused` с причиной, без запасного пути.

## Тесты

`backend/tests/test_script_runs.py` (8, настоящий supervisor-процесс и Docker):
запуск с журналом, бюджетом и зарегистрированным выходом; повтор без второго
job; принятие результата у supervisor-а после гибели воркера; выключенный
флажок; недоступный supervisor; вход Боба; таймаут; отмена убивает работающий
скрипт. `infra/agent-script-supervisor/tests` — 14 (в том числе отмена до
прихода запуска).
