# E35 — файлы браузера через брокер артефактов

Дата: 10 октября 2026.

## Загрузки (сайт → система)

- Сервис браузера ловит загрузки во всех вкладках сессии (не более 5 на
  сессию). Ждёт завершения не дольше `BROWSER_DOWNLOAD_MAX_SECONDS` (120 с) —
  иначе отмена, `too_slow`; файл больше `BROWSER_DOWNLOAD_MAX_BYTES` (25 МБ) —
  `too_large`. Бесконечный поток не заполнит диск до таймаута: прокси выхода
  режет любой ответ сверх `BROWSER_EGRESS_MAX_RESPONSE_BYTES` (100 МБ).
- Файл держится в памяти сессии с sha256 и типом по сигнатуре; временный файл
  браузера удаляется. Имя из `Content-Disposition` — только метка: базовое имя,
  ASCII, без путей и `..`.
- `desktop_downloads` — список; `desktop_save_download {download_id}` — бэкенд
  забирает файл этой сессии (чужой id — `download_not_found`) и регистрирует его
  через брокер (E28): сверка размера и хэша, отказ исполняемым, хранение по
  sha256 без перезаписи, `artifact_type=browser_download`, в метаданных —
  исходный URL, тип, грант. Архивы не распаковываются, файлы не запускаются.

## Выгрузка (система → сайт)

- `desktop_upload {ref, revision, inputs: [{artifact_id, sha256, name}]}`:
  только артефакты владельца заказа, байты сверяются с sha256
  (`materialize_inputs`), имя — безопасное плоское; путей хоста в браузер не
  попадает — файлы передаются в памяти и кладутся только в `input[type=file]`.
- Отозванный артефакт (`POST /api/work-orders/{id}/artifacts/{aid}/revoke`,
  владелец) больше не вход ни для браузера, ни для скриптов.
