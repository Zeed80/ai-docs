# E39 (кэши) и E40 — графовые обходы и охрана объектов

Дата: 10 октября 2026.

## Кэши (остаток E39)

- `result_cache` (быстрый ответ «сколько счетов/документов», 15 с) хранил ответ
  под ключом без пользователя: число, посчитанное по правам одного, получал
  следующий. Теперь ключ включает область действующего пользователя
  (`actor_context.cache_scope()`, хэш sub). Нет пользователя — нет кэша.
- `flow_awareness` (снимок потока для промпта, 20 с, среди счётчиков —
  непрочитанная почта) был одним глобальным ключом — теперь по пользователю.
- `skill_cache` никем не вызывается, но ключ так же привязан к пользователю,
  чтобы будущий вызов не открыл утечку.
- Отзыв прав ждёт не дольше TTL (15–20 с); кэшей с долгим TTL на данных нет.
- `orchestrator_memory` хранит статистику инструментов, не данные.

## Граф (E40)

Единая политика — `app/domain/graph_access.py` (`GraphAccess`), та же в SQL
агента (`aiw_rls_node`, `aiw_rls_evidence`):

- Узел документа или сущности виден, когда видны документ и сущность
  (документ, счёт, письмо или черновик письма, аномалия/согласование о них).
  Удалённый источник — узел скрыт.
- Узел, собранный регуляркой из упоминаний (ИНН, адрес, имя), без источника и
  сущности, несёт текст чужих документов: виден, только если пользователь видит
  хотя бы один документ, который его упоминает. Без документной опоры —
  общие данные (поставщик, ручной узел).
- Ребро — оба конца, его документ и документ его evidence.
- Окрестность, путь и зависимости документа обходят только видимое: путь через
  разрешённый узел не выходит к закрытому соседу. Невидимый узел отвечает 404,
  как отсутствующий. Создание рёбер и упоминаний — только на видимом.
- Поиск памяти отсекает узлы по той же политике и evidence по его документу.

## Охрана /{id} (найдено при аудите E40)

`/api/documents/{id}`, `/api/invoices/{id}`, `/api/cases/{id}` (и вложенные:
скачивание, правка, удаление, счёт документа, зависимости), а также
`/ntd/documents/{id}`, `/export/invoices/{id}`, `/payments/invoices/{id}`
загружали строку по id без проверки прав — фильтровался только список. Теперь
у роутеров общая зависимость `access.path_object_guard`: объект, который
пользователь не видит, отвечает 404. Новый маршрут с тем же параметром закрыт
автоматически.

## Каталоги поставщиков — общие

После backfill (`20261010_0003`) каталоги получили владельца, и исправленный
`visibility_filter` скрыл бы их от других отделов. Каталог — справочник
предприятия: `access.SHARED_DOCUMENT_TYPES = ("supplier_catalog",)` виден всем
через `document_visibility_filter`, охрану `/{id}`, граф и RLS
(`aiw_rls_shared_type`). Владелец остаётся как происхождение.

## Попутно в RLS

`draft_actions` проверялись только по сущности, а у черновика письма её нет:
тексты черновиков из личных ящиков были видны через SQL агента. Правило
повторяет `may_access_draft`: автор или ящик, который пользователь видит.

## Живой прогон

После выката: RLS переустановлен (`9adf5c1606d4ded6`), `count(*)` по 18 тыс.
узлов и рёбер — 2–4 с. Администратору не видны 10 узлов согласований отправки:
их черновики удалены, id нет ни в одной таблице — скрытие правильное.
