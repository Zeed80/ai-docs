# vl-embedding — поиск по картинке

Сервис превращает картинку **и** текст в векторы одного пространства
(Qwen3-VL-Embedding-2B, Apache-2.0). Благодаря этому фотография инструмента,
кроп из каталога поставщика и фраза «алмазный круг 100x10» сравнимы напрямую —
одна коллекция Qdrant отвечает и на фото, и на слова, и на «покажи похожие».

## Зачем отдельный сервис

Эмбеддинги проекта идут через Ollama, а её `/api/embed` принимает поле `images`
и **молча его игнорирует** — вектор описывает только текст (замерено на стенде).
Поиска по картинке так не получить ни при каких настройках. Поэтому модель,
которая это умеет, вынесена в контейнер со своим стеком torch/CUDA — тем же
приёмом, что и `infra/technical-vectorizer`.

## Ресурсы и поведение под нагрузкой

Карта на стенде одна (RTX 3090, 24 ГБ) и делится с LLM. Отсюда два правила:

- веса выгружаются после `VL_EMBEDDING_IDLE_UNLOAD_SECONDS` простоя (по
  умолчанию 600) и грузятся заново за несколько секунд;
- если VRAM занята, модель поднимается на CPU и `/info` честно показывает
  `device: "cpu"`. Медленно — это не то же самое, что сломано.

`/health` намеренно **не** загружает модель: healthcheck раз в 30 секунд иначе
держал бы 4.5 ГБ VRAM постоянно и обессмыслил выгрузку.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `VL_EMBEDDING_MODEL` | `Qwen/Qwen3-VL-Embedding-2B` | модель HuggingFace |
| `VL_EMBEDDING_DIM` | `1024` (в compose) | усечение вектора (MRL), нативно 2048 |
| `VL_EMBEDDING_IDLE_UNLOAD_SECONDS` | `600` | через сколько простоя выгружать веса |
| `VL_EMBEDDING_MAX_BATCH` | `16` | больше — не быстрее, а только пик VRAM |
| `VL_EMBEDDING_MAX_PIXELS` | `1024` | длинная сторона входной картинки |

**Смена `VL_EMBEDDING_DIM` или модели требует переиндексации**: размерность —
часть схемы коллекции Qdrant. Задача `catalog.visual_index_batch` сама заметит
смену модели (в записи хранится `visual_model`) и переиндексирует, а вот
коллекцию с другой размерностью придётся пересоздать.

## API

```
GET  /health   живость; модель не грузит
GET  /info     модель, размерность, устройство
POST /embed    {"items":[{"text":"…","image_base64":"…"}], "prompt":"…"}
```

Картинка передаётся байтами в base64, а не ссылкой: сервис внутренний и не
должен ходить в сеть по чужому адресу.

## Веса

Скачиваются один раз в том `vl_embedding_models` (~4 ГБ) при первом обращении
к `/info` или `/embed`. Отдельного шага установки нет.

## Как это используется

- `backend/app/ai/vl_embeddings.py` — клиент (в degraded-режиме возвращает
  `None`, а не падает);
- `backend/app/tasks/catalog_visual.py` — индексация кропов партиями с
  чекпоинтом в самой записи;
- `POST /api/catalogs/search-visual` — поиск по фото/словам/`entry_id`;
- capability агента `tool_catalog.search_visual`;
- страница «Каталоги → Поиск по позициям»: «Найти по фото» (в мобильном
  приложении — «Сфотографировать», через плагин камеры).

Если сервис недоступен, поиск по картинке отвечает `available=false` и **не**
подменяет себя текстовым поиском — иначе выключенная функция выглядит
работающей.
